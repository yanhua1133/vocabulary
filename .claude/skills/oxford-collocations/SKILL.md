# 牛津搭配词典重排

**工作目录：`oxford-collocations/`**，命令先 `cd oxford-collocations`，
解释器用 `../.venv/bin/python`。

**管线已跑通**。成品是 `牛津搭配词典 重排版.pdf`（约 3200 页）和
`out/牛津搭配词典.md`（四列：单词 / 搭配 / 解释 / 例句，8.2 万行）。
原书 `牛津搭配词典.pdf`（2058 页、499 MB）不入库。
**全部踩坑记录在 `data/progress.md`，动手前必读**。

## 这本书的情况

- **纯扫描件**（Pdg2Pic 生成，每页一张图、零文字层），跟牛津习语词典同类，**只能 OCR**。
- **2058 页，是习语词典的 3.3 倍**——OCR 和子 agent 的批次都要按这个量级重新估算，
  别照搬习语词典的并发数。开工前先抽几页看版式（单栏还是双栏、每个词条怎么分块）。
- 搭配词典的结构跟习语词典不一样：一个词头下面是按词性/搭配类型分组的**词块列表**
  （ADJ. / VERB + NOUN / PREP. 等），不是一条条独立习语。抽取判据要重新设计，
  不能直接套 `02_entries.py`。

## 起步方式

**照抄 `oxford-idioms/` 的管线骨架，但判据要重写。** 那本书的
`data/progress.md` 记着全部踩坑记录，动手前必读，尤其这几条是跨书通用的：

1. OCR 用 macOS Vision，`language_preference` 第一位**必须**是 `zh-Hans`，
   写成 `en-US` 在前中文整段丢失。220dpi 够用。机器上的 tesseract 只有 eng。
2. Vision 会**静默丢整行**，而且丢的多半是加粗的条目行。必须靠「相邻行 y 间距
   超过正常行距 1.75 倍」检测并重 OCR 补回（那本补回 1834 行）。
3. Vision 还会把一行**切成几块**，y 只差千分之几。必须按行合并，否则语序全乱。
   合并要加两个保护：碎片横向不能重叠；大字号的词头片段不能并进上一行。
4. **字重判据不可用**——Vision 的行 bbox 不够准，量笔画宽度时粗体反而比正文细。
   只能靠版面规律 + 重音符号之类的文本特征。
5. 子 agent 遇到 OCR 残片会**自己猜一条真实存在的词条填上**，猜得对不对无从验证。
   必须在渲染层用「原始行与模型输出有没有实质公共内容」把这些剔掉。
6. 缓存按上游序号存，**所有清洗都放渲染层**，别回头改抽取脚本。

## 交差前必须跑自查，跑到收敛

`scripts/08_audit.py` 把踩过的坑逐条查一遍，**查的是渲染成品的每个格子**，
不是中间数据。已校对和未校对分开统计——未校对的就是原始 OCR，问题多是正常的，
要看的是**已校对部分的「处/行」有没有降下来**。

流程是：跑自查 → 看还剩哪几类 → 分辨是真错还是误报 →
真错就修管线或导出给子 agent → 重新渲染 → **再跑自查**，直到数字不再下降。
一轮下来是 210 → 208 → 193 → 191 → 70 → 65 处。

查的七类，每条都对应真犯过的错：

| 类别 | 长什么样 |
|---|---|
| 搭配夹数字 | `g00d`、`detedt`（OCR 把字母认成数字，纠错时被 `isalpha()` 挡在门外） |
| 搭配其实是句子 | `s this an appropriate time to discuss salary?`（正文被抽成搭配，还掉了首字母 I） |
| 搭配有坏词 | `ocal`→local、`conciderahle`→considerable |
| 解释混英文 | 没摘干净的例句 |
| 解释为空 | 抽取时被串行吃掉了 |
| 例句不完整 | 缺主语、没有句末标点 |
| 搭配缺首字母 | `n accepting the award`、`m expecting a call`（首字母被吃掉，单字母打头） |
| 例句加粗不全 | 多半不是加粗的错，而是**例句压根没用上搭配**（同义表达） |
| 搭配只有一个词 | `age`（其实是 school age）、`provide`（provide accommodation）——`~` 丢了 |
| 解释混进句子 | 例句译文和下一个小类的义项被一路吃进解释格 |
| 解释夹空格/方括号 | `评论界的赞扬 ］`、`在… 方面表现积极` |
| 解释里的孤立「一」 | 是省略号被认成汉字：`向一踢` 其实是 `向…踢` |
| 括号不配对 | `对…踢；违抗…(`——切成义项之后两半分家，要**切完再判** |

## 解释列是「一串短义项」，不是句子

`09_clean.py::clean_gloss`：按分隔符切成义项，**逐条判**，像句子的整条扔掉。
用户点名过的三条：`kick at`→`向一踢`、`kick against`→`对⋯踢；违抗⋯(`、
`kiss on`→`在⋯上的一吻！`。

- **分隔符不止分号**：原书竖线被 OCR 认成 `；。，、！：？` 各种样子，
  `狠狠的！使劲的` 里的感叹号就是竖线，原样印出来像在喊。
- **整段从句号处截断太狠**：`习得力。培养；增强；提高能力` 会白丢三条正经义项。
- 判「这条是句子」用人称/指示代词、句末语气词、长度 >15。**长度不能卡紧**，
  `白人儿童与少数族裔儿童学习成绩的差异` 是正经义项。
- 孤立「一」只在介词后面、jieba 切成单字时才换成省略号；切成 `一所`/`一体`
  这类量词短语就换不了，那一条整条扔掉——硬换会毁掉 `融为一体`、`倾向一边`。
- **凡是判据依赖整格上下文，收敛就是碰运气**：写成「整格里别处有省略号就放过
  这一条」，同一条解释清两遍出两个样，自查卡在 1 处永远降不下去。
- **解释空了就整行不印**（不许空白单元格），也不许拿合并单元格糊弄。

## 排 PDF 的四个坑（`13_pdf.py::verify` 每次都要跑）

1. **除第一页全都没表头**：`re.findall(r"<tr>.*?</tr>")` 捞出来的表头丢了外面
   那层 `<thead>`，拼回 `<table>` 时浏览器把它塞进 tbody，
   `querySelector('thead')` 是 null，`PAGINATE_JS` 一份表头也插不进去。
   **第 1 页看着完全正常**（它就是 tbody 第一行），只翻头几页永远发现不了。
   拼片必须写成 `<table><thead>…</thead>`。
2. **行高由最高那一格定，别单独缩矮列的字**：搭配一格七条、整行已占 7 行时，
   还按「解释列最多两行」缩字号纯粹是把字缩成蚂蚁换空白。
   先把搭配列压到 14 行内，**它就是这一行的地板**，其余列上限取 `max(2, 地板)`。
3. **软下限 6pt，先折行再降号**：缩到 6pt 还放不下就放宽一到两行。
   放宽行数之后**必须给「涨回去」的循环加原始字号封顶**——一格能放的字变多了，
   那循环会把字一路涨到 9pt 多，满页正文里冒出一格特大号字，比缩小还难看。
4. **自查要读成品 PDF**，逐页查表头四个字在不在。
   **fitz 的 `span["size"]` 就是 pt**，别乘 `96/72`——多乘一遍把 5.2pt 报成 3.9pt。

**改过一轮之后要对账**。自查导出 id 用的是修正后的搭配、渲染查缓存用的是抽取阶段的
原始搭配，改一轮两边就对不上——修好的东西写进了一个渲染永远读不到的孤儿 key，
成品里显示的还是旧内容，自查报的数字也就一直降不下去。
`06_merge.py::reconcile` 负责把孤儿 key 搬回去。

**分辨误报同样重要**，否则会把对的改坏：`a 16-digit number` 的数字是正经的、
`what use is sth?` 是词典收的固定表达、`belabour`/`practise` 是英式拼写、
`semidetached`/`pityingly` 是 wordfreq 收不全的派生词。每加一条判据都要先看误伤。

## 工作纪律

跟 `oxford-idioms` 一致：每轮产出能打开的文件；子 agent 的报告逐条核；
过滤判据先量化误伤再上；排版改完必须看图；每块结束更新 `data/progress.md`；
回话只给数字和路径，全中文。
