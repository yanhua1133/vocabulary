## 第三轮：用户点名的三个问题（2026-08-08）

### 一、除第一页，全书都没有表头
`render_chunked` 切片时用 `re.findall(r"<tr>.*?</tr>")` 捞行，捞出来的表头是
光秃秃的 `<tr><th>…</th></tr>`，外面那层 `<thead>` 被留在了原地。
直接拼进 `<table>`，浏览器会把它自动塞进 tbody，
`document.querySelector('thead')` 就是 **null** —— `PAGINATE_JS` 因此
一份表头都插不进去，`headH` 也是 0。
**第 1 页看着完全正常**（它就是 tbody 的第一行），只翻头几页永远发现不了。
拼片必须写成 `<table><thead>` + 表头行 + `</thead>`。

### 二、搭配占了 7 行，解释还在缩字号
`good kick / hard kick / hefty kick / powerful kick / sharp kick / swift kick /
vicious kick` 一格七条，整行已经占了 7 行；`SHRINK_JS` 还按
「解释列最多两行」把它缩到 5.2pt —— 行高本来就由最高的那一格定死，
缩矮列一个字号也省不出来，纯粹是把字缩成蚂蚁换一片空白。
改成**行内相对判断**：先把搭配列压到 14 行以内，**它就是这一行的地板**，
其余列的上限取 `max(2, 地板)`，只有比整行还高的格子才需要压。

还加了**软下限 6pt**：缩到 6pt 还放不下就放宽一到两行。用户的原则是
「先折行再降号」，缩到 4.7pt 去换半行空白是本末倒置。全书最小字号
从 4.7pt 升到 6.0pt，6pt 以上占 100%。
**放宽行数上限之后必须给「涨回去」的循环加上原始字号的封顶**——
一格能放的字变多了，那个循环会一路把字涨到 9pt 多，
满页正文里冒出一格特大号字，比缩小还难看（样张上一眼就看见）。

### 三、解释列印出来不是人话
`kick at` → `向一踢`、`kick against` → `对⋯踢；违抗⋯(`、
`kiss on` → `在⋯上的一吻！`。新增 `09_clean.py::clean_gloss`：
**解释列是「一串短义项」，不是句子**。

- **按分隔符切成义项，逐条判，句子混进来的整条扔掉。** OCR 常把例句译文和
  下一个小类的义项一路吃进解释格。整段从句号处截断太狠——
  `习得力。培养；增强；提高能力` 会白丢三条正经义项。判「这条是句子」用
  人称/指示代词、句末语气词、长度 >15；**长度不能卡紧**，
  `白人儿童与少数族裔儿童学习成绩的差异` 是正经义项。
- **分隔符不止分号**：原书的竖线被 OCR 认成 `；。，、！：？` 各种样子。
  `狠狠的！使劲的` 里的感叹号就是竖线，原样印出来像在喊。
- **括号要切完再判**。整格的括号是配对的，切成义项之后两半分家：
  `(乳酪等)` 里 `乳` 被认成拉丁字母、又被换成分号，切出来就是一个光括号
  加 `酪等)`。孤立括号只抹掉那个字符，别整段截断——后面往往还有正经义项。
- **`一` 是省略号被认成汉字**（`向一踢` 应是 `向…踢`）。只在介词后面动手，
  jieba 把它切成单字才换；切成 `一所`/`一捆`/`一体` 这类量词短语就换不了，
  那一条直接扔掉——硬换会毁掉 `融为一体`、`倾向一边`。
- **逐条判，不能看整格**。第一版写的是「整格里别处有省略号就放过这一条」，
  结果同一条解释清两遍出两个样（`为一的做法` 第二遍才被修），
  自查数字卡在 1 处降不下去。凡是判据依赖整格上下文，收敛就是碰运气。
- **解释空了就整行不印**（`clean_row`）。不许有空白单元格，也不许合并糊弄。

搭配列顺带补两条判据（共命中 46 条，全是真错）：
- **句点后面不管跟大写、小写还是数字，一律算坏**：原来只卡
  `[a-z]\.\s+[a-z]`，`asbestos. Carbon lib`、`modules. 1 complete`、
  `acted cool toward you. (AmE)` 三种全漏。但要放过词典缩写
  （`(esp. BrE)`、`etc.`），不然误伤一大片。
- 游离的句点逗号：`manufacture .BrE steel`、`replacements' .subs' bench`。

`07_render.bold_words` 把 `</b>-<b>` 也并起来——`<b>great</b>-<b>aunt</b>`
看着像中间那杠标漏了。自查里对应加了「拼写变体算同一个词」的误报过滤
（`grey`/`gray`、`armour`/`armor`、`fibre`/`fiber`，编辑距离 ≤1 含相邻换位）。

## 第二轮修的（2026-08-07）

### 中文列（占全书 38.6% 的行有问题）
- **汉字之间的空格要分两种处理**，一律删或一律留都不对：
  `明确表 示钦佩` 是 OCR 把词拆开了（要合上），`富有创意的 想象丰富的` 是义项分隔（要换成分号）。
  靠 jieba 分词判：把两边接起来切词，切点落在某个词**内部**就是拆开的。
- 半角标点（18%）夹在汉字里字距明显不对，一律换全角。句号要**先**换——
  它两边常带空格（`勉强承认 . 她不承认`），不先换掉后面按空格切义项会把一句话劈成两段。
- 例句译文跟解释列不一样：它是连贯的一句话，汉字间**不该有任何空格**，
  也不该按义项分隔处理。

### 形近误认（`t0`=to、`advance5`=advances、`claim0f`=claim of）
跟习语词典同一套 `respell`：按形近逐个回代，wordfreq 验证是不是真词。三个坑：
- **短 token 不能走「本来就是词」的捷径**——`t0` 在语料里也有频率，放过去就修不掉。
- 数字把两个词粘住时要**切开**（`claim0f` → claim of）。候选很多（1 可以还原成 l/i/t），
  要挑两半词频之和**最高**的，取第一个撞上的会得到 `aspect lo`（正确是 `aspect to`）。
- `colony5` = colonies 这种复数得整段换，逐字符替换救不回来。
- 还原不了的（`hiccups5`）整条不印——留着就是印错。

### 词头被组标签污染（161 个义项 / 3927 条搭配）
`04_expand` 把组标签 `ABSCESS + VERB` 当成了义项词头，于是整个 `abortion` 词条
变成了 `abscess`，`ask`→`aspect`、`army`→`aroma`、`bail`→`ball`——**填进去的都是
字母序上相邻的下一个词**。判据：`sense.head` **只在它本身也是本书词头时才采信**
（`abscess` 根本不在词头表里）。另外整组搭配都含同一个非词头的词时，
把它换回真正的词头（`have abscess` → `have abortion`）。

### 空白单元格

全部走 `16_make_ex.py` → agent 自拟 → `17_merge_ex.py` 回填，中译标「（自拟）」。

## 抽取判据踩的坑
1. **`\b` 把带点词性全废了**：`HEAD_RE` 末尾写 `\b`，而 POS 里的 `\.?` 会吃掉那个点，
   `adj.` 之后是句点+行尾构不成单词边界 —— 结果 adj./adv./prep. 的词头全军覆没
   （词头 5596 → 去掉 `\b` 后 6501）。
2. **正则交替要长的在前**：`ad` 排在 `adv`/`adj` 前面会先吃掉前缀再卡住。
3. **标签和搭配词之间不一定有空格**：OCR 出来常是 `ADJ.draft`，
   点后面的空格必须可选，否则整组被并进义项文本（搭配组 17790 → 20711）。
4. **别把 NUMBER 当组标签**：例句里换行开头的 number 会被误判，还会把真组腰斩（12 处）。
5. **跨页续尾要接上**：每页各扫各的，页首那些续行没有归属就被丢了。
   现在标成 `cont` 交给主循环拼回上一页最后一块。

## 拆分踩的坑
- 例句引导符 `◇` **最常被 OCR 并成中文句号**（`协议 。 They are working…`），
  只认 `•◎*` 的话例句只能抽到 11%；补上「中文 + 句号 + 大写英文」这条后到 60%。
  句号前还可能有空格，后行断言要写成 `(?<=[\u4e00-\u9fff])\s*[。.;:]\s*`。
- **得先摘例句再切小类**。反过来的话，例句里的标点会把小类切得稀碎（90818 → 76196）。
- 代替词头的 `~` 常被认成汉字「一」，夹在英文中间时要还原——不还原的话
  「例句里不含汉字」这条边界判据就断了。

## 词头漏识别：一个基线取错，1673 个词头集体消失
子 agent 报告 `pure please`、`lucrative Care`、`solo CareS` 这些病句，查下来是
`pleasure`、`career` 整个词条的搭配都挂到了前一个词头上。根子在**顶格基线取了最小值**：
`pleasure noun` 的 x=0.063，而那一栏有个异常行 x=0.05，差 0.013 超过阈值 0.012，
词头就被当成缩进续行丢了。改用 15% 分位当基线后词头 6092 → 7765。

连带修的两个：
- **页眉过滤**：页眉是 `pleased 1282`（书眉词 + 页码）在 y≈0.06，阈值卡 0.045 全漏。
  但也不能单纯按 y 切——切到 0.08 会把栏顶的词头（`can noun`）一起切掉，
  只能认「页顶 + 带页码数字」的那种。
- **假词头**：`more`、`S`、`got a`、`has helped reduce the`、`AVOCADD t` 这些是从正文里
  捞出来的。规则：最多两个词、每个词至少两个字母、都不能是虚词
  （`baby carriage`、`black market` 要留住）。最终词头 7948。

## 词头 OCR 纠错
子 agent 报 `ow point`、`ife point`、`biock`、`coai` 这些——词头一错整个词条就查不到。
两类毛病：首字母被吃掉（`djective`→`adjective`、`elegate`→`delegate`）、
形近字母认错（`biock`→`block`、`assauit`→`assault`、`cuiture`→`culture`）。
用 wordfreq 兜底：原词本身不是常见词、且补首字母或换一个形近字母后候选唯一又够常见，
才改。坏词头 120 → 48（剩下的是多字母同时认错，如 `lecorative`、`commierce`）。

## 词头串位：三个连环坑
`ablaze` 名下曾经挂着 `have ablaze`、`retain ablaze`——那些其实是 `ability` 的搭配。
根子是合并碎行时没保护词头，连修三次才干净：
1. 词头片段**不能并进上一行**（`ablaze ad.` 被并进了 abhorrent 的 VERBS 行）。
2. 词头行**也不能把后面的碎片吸进来**——`ablaze adj.` 吞掉 ability 的 ADJ 续行后，
   它在栏内的位置就跑到 ability 前面去了，把人家十几条搭配全领走。
3. **补回来的行只能当续行，除非整行干干净净只有「词 + 词性」**。
   `ablaze adj. * đ „*x c` 就是 gapfill 补出来的乱码，还落在右栏中间。
   一刀切地不让补行开词条会丢 738 个真词头，所以加了「整行无尾巴」这个条件。

## 首字母被扫描件吃掉：规则能修，别只交给 agent
`n accepting the award`（in）、`m expecting a call`（am）、`t is accountable`（it）、
`s this an appropriate time`（is）——扫描件左边缘常把行首第一个字母切掉，剩个孤字母。
这类**全书 341 处**，我一开始只在已校对的 3535 行里让 agent 修，
未校对的 94978 行里照样在，用户一眼就看见了。

`04_expand.py::fix_lone_letter` 用固定映射修：wordfreq 只有单词频率、比不了词组，
`in` 和 `an` 分不出高下，所以直接写死 n→in、m→am、t→it、s→is、f→of、e→be、
y→by、o→to、r→or、g→go、p→up。两个坑：
- 后面跟的词卡两个字母就够（`t is accountable` 的 is 只有两个字母，卡三个会漏掉一大半）；
- 补出来的词要跟后面那个词比一下，别把 `o to` 补成 `to to`；
- **前面必须是空格或行首**，用 `\b` 会把 `couldn't believe` 里的 t 当成孤立字母，
  补成 `couldn'it believe`——我就是这么把已校对部分从 57 处搞回 97 处的，
  改完一定要重跑自查看数字有没有反弹。

## 例句里搭配要整条加粗
原来逐词标、还特意跳过虚词，结果 `a matter of time` 只有 matter 和 time 是黑的，
中间夹着没加粗的 a 和 of，看着像标漏了。改成**整条短语匹配**：
- `a/the` 这种二选一转成正则的「或」，不然 `in a/the system` 永远对不上
  例句里的 `in the system`；
- 词之间允许屈折后缀和插进一两个修饰语；
- 前后要卡词边界，否则 `in` 会匹配到 `links` 里面去；
- 整条对不上才退回逐词标（`clog system` 在例句里是 `clogging up the court system`）。
- **词尾的 e / y 要单独处理**（`09_clean.py::inflect`）：直接在词尾接 `\w{0,4}`
  的话 `ache` 匹配不上 `aching`、`carry` 匹配不上 `carried`；但把 e 一律砍掉又太松，
  `care` 会把光秃秃的 `car` 也标黑。
- **不规则动词要列表**：例句里全是 `sent` `took` `made`，跟搭配里的原形对不上，
  光这一类就漏标 300 多处。
- 例句里也常把两种拼法一起写（`They honour/honor their ancestors`），
  前后各留一个 `词/` 的口子，不然只标得住后半截。
- 一格里好几条搭配，整条标完再逐词标会套出 `<b>finished our <b>business</b></b>`，
  按深度扫一遍只留最外层。

## 单词列：合并 + 跨页重写（**自己控制分页**）
- 表头叫「单词」。
- **真正合并**：`border-collapse` 下光去掉续行格的上边框没用，上一格的下边框还在，
  横线照样一条条画。得把这一列的横线全撤掉，再单独给「换了单词」的那格补上边框。
- **不用真表格布局**。Chrome 打印时不认 `tr` 的 `break-inside: avoid`，行照样被
  分页拦腰切断（页顶经常是半句中文）。改成 `display: flex` 的伪表格，
  block 级元素的 break-inside 它是认的；列宽从 `width` 改成 `flex-basis`，
  边框也得改成每格只画右下（flex 下 border-collapse 失效）。
- **分页自己算**。JS 在 print 模拟下看到的是连续流，量不出 Chrome 把页切在哪儿；
  按页高整除也不准（它会为了不切断行上下浮动）。干脆自己来：量每行高度累加，
  超过一页正文高度就给那行打 `break-before: page`，同时
  ① 把单词补写到这一行的第一列（补完要**重新量一次行高**，补字会让行变高）；
  ② 插一份表头进去（flex 下 `thead` 不会自动重复）。
- **每页最后要封口**：单词列整列没有横线，翻页时上一页最后那格就没了底边、开着口。
  分页时给上一行的单词格补一条下边框，整张表的最后一行也补。
- 结果：样张 14 页，**14/14 页第一列顶上有单词、13/14 页有表头**，
  行零切断，每页底边横线都从 x=31.5 起（盖住第一列）。
- **改 display 之前先把旧规则清干净**：早先为了让表头每页重复写过一条
  `thead { display: table-header-group }`，改 flex 布局时忘了删，它压住了
  `thead { display: block }`——第 1 页的表头因此没走 flex，四列塌成按内容宽排，
  「单词」被挤成上下两个字，竖线冒出七条。第 2 页起用的是 JS 克隆进 tbody 的
  表头，反而是对的，一眼看不出问题在哪。
- 列宽用 `flex: 0 0 26%` 一次写全，别写成 `flex: 0 0 auto` 再补 `flex-basis`。
- 踩坑记录：验证时差点误判成没生效——第 2 页起没有大标题，正文从 y≈40 就开始，
  而我按第 1 页的排布卡了 `y > 80`，把页顶那几行全过滤掉了。

## 版面：rowspan 会让 td.cellIndex 左移
排版脚本原来按 `td.cellIndex` 取每列的行数上限和字号下限。有 rowspan 时，
**没有词头格的那些行 cellIndex 会整体左移一位**——搭配列被当成词头列，
按「最多两行、可以缩到 2.9pt」处理，于是多条搭配的格子被压成一团蚂蚁。
改成渲染时给每个 td 打 `c1`~`c4` 的 class，脚本按 class 认列。
修完样张里小于 5.5pt 的字符占比 0.0%。

另外两条：
- **每列的行数上限按内容定**：搭配列 14 行（一格能有八九条搭配，竖排本来就该占那么多），
  解释和例句 3 行，词头 2 行。宁可行高参差，也不要小到没法读。
- **词头列不能用 rowspan**：`system` 这种词条几百行，rowspan 一跨页，Chrome 会把
  那一格的边框重画一遍，第一、二列之间冒出两条竖线（x=81.0 和 81.8 并排），
  格子高度还算错、竖线直接戳出表格底边。改成每行都出一个 td，
  空的那些加 `.cont` 去掉上边框——看着照样是合并的，没有跨页毛病。
- **放不下时先拆中英换行、再考虑缩字号**。顺序反了会很难看：
  `under the new system, all children will be monitored by a social worker.`
  这种英文正好占满一行的，缩字号是把整格都缩小，而把中文接到英文后面连排，
  省下一整行、原样两行就放下了。改完 7pt 的占比从 63% 升到 94%，最小 5.8pt。
- **例句里搭配要整个加粗，不是挑几个词**。词形变化的后缀余量要给够：
  `clog` 在例句里是 `clogging`，只留 3 个字母的余量就匹配不上，
  那条搭配等于没标。占位词（sb/sth/a/the）跳过。
- **解释和例句一律压两行**：给三行的余地，脚本一看放得下就不缩字号了，
  结果 `An ancient irrigation system still waters these terraced / fields. /
  一套古老的灌溉系统仍在浇灌这些梯田。` 排成三行，`fields.` 半截单独占一行，
  而旁边几列都只有两行。宁可字号缩一点也要压平。搭配列例外（一格能有八九条）。

- **门槛要用相对值**。卡「查不到的词」不行——`ife` 的词频有 2.69 却是 life 掉了首字母。
