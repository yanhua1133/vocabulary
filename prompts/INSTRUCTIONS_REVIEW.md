# 语义复核批次规则

给你若干 `work/batches/REV_NNN.json`。每个是 JSON 数组，元素是一个已经填好的词条：

```json
{"word": "abase", "ipa": "əˈbeɪs", "cn": "降低（地位、威望、尊严）", "pos": "v.",
 "phrase": "abase oneself before someone", "phrase_cn": "在某人面前自贬",
 "example": "He would not abase himself by begging for the job.  他不愿低声下气地乞求这份工作。",
 "spoken": 1, "related_to": ""}
```

你的任务是**逐条复核内容是否正确**，只把**需要修正**的词写进输出。

对每个文件：`Read` 它，然后 `Write` 同名 `.out.json`，内容是一个 JSON 对象：
键 = 需要修正的 `word` 原样字符串，值 = 只含**你要改的那些字段**的对象。
**完全正确的词不要出现在输出里。** 如果一批全对，就写 `{}`。

## 逐字段检查什么

1. **ipa** — 音标是否是该词真实的美式读音？重音位置对不对？
   多音节词是否漏了音节？只用这些字符：
   `ˈ ˌ ː a ɑ ɒ æ ʌ e ɛ ɜ ə ɪ i ɔ o ʊ u b d f ɡ h j k l m n p r s t v w z ʃ ʒ θ ð ŋ` 和空格；
   必须用 `ɡ`(U+0261)，不带斜线方括号。
2. **cn** — 中文释义是否准确？是否是该词的**主要**义项？
   `related_to` 非空时，该词是那个词的近义词或反义词，释义必须落在**那个语境**上
   （例如 `related_to` 是 abase 时，`foul` 该解释为「玷污（名誉）」而不是「足球犯规」）。
   ≤20 字，纯简体中文，多义用「；」分隔。
3. **pos** — 词性是否正确？只用 `n. v. vt. vi. adj. adv. prep. conj. pron. num.`，多个用 `/`。
   注意名词被误标动词、形容词被误标副词这类错误。
4. **phrase / phrase_cn** — 搭配是否地道、是否真含该词？中文是否对得上？
5. **example** — 英文句子语法是否正确、是否自然、是否真的用对了该词的这个义项？
   中文翻译是否准确、是否有漏译错译？格式必须是「英文句 + 两个空格 + 中文」，
   英文句首字母大写、句末有标点、8-20 词。
6. **spoken** — 0-5 整数，该词在**日常口语**里出现的可能性（5=口语极常见，0=只见于正式书面语）。
   明显偏离的才改，比如 GRE 生僻书面词被标成 4-5，或 say/talk 这类被标成 0-1。

## 硬要求

- 只输出**确实有问题**的词；不要为了凑数改动正确的内容。
- 输出的每个字段都必须是修正后的完整值，不要写「同上」或说明文字。
- 只输出裸 JSON，不要代码围栏，不要解释。
- 汇报时说明：这批检查了多少词、改了多少词、改的主要是哪类问题。
