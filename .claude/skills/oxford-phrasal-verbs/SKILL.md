## 这本书的情况

- **纯扫描件**（FreePic2Pdf 生成，每页一张图、零文字层），跟牛津习语词典同一套
  制作工具、同样的版式路数，四本书里复用度最高的就是这本。
- 双栏。每栏四类行：词头（动词 + 音标）、短语动词条目（**悬挂缩进 + 重音符号**）、
  标签行（OBJ / SYN / OPP / NOTE，原书是反白小方块）、模式行（`◆ v + adv`）。
- **释义和例句跟条目挤在同一段里**，不像习语词典那样各占一行。
  所以 `02_entries` 只切「条目块」，字段拆分单独放在 `03_split`。
- **四列输出：动词 / 短语动词 / 释义 / 例句。语法模式（`v + prep`）整个不印。**
  用户砍掉这一列之后我把它塞回短语动词格里用小字标，等于没砍，又挨一次骂。
  **用户说「这列不需要」是说这个信息不要，不是换个地方摆。**
  数据还在 `rows.json` 里，要用再说。

## 复用哪一本

- **OCR 和补行**（`01_ocr` / `03_gapfill`）拷 `oxford-idioms/`，只改书名和页码。
- **清洗和排版**（`09_clean` / `13_pdf`）拷 `oxford-collocations/`：
  中文清洗（汉字间空格按 jieba 判、半角标点转全角、释义按义项逐条判）和排版三件套
  （表头必须包 `<thead>`、按行相对缩字号、6pt 软下限 + 原始字号封顶）原样可用。
  **但列的判据必须改**：短语动词的重音符号 ˈ ˌ 要留着，
  拿搭配那套 `[A-Za-z]+` 取词会把 `aˈgree` 切成 `a` + `gree` 判成坏词，
  例句比对也永远对不上——**光这一个 bug 就丢掉 4143 句例句**。

动手前必读 `oxford-idioms/data/progress.md`，那里是这套管线的全部踩坑记录。
最要紧的几条：

1. OCR 用 macOS Vision，`language_preference` 第一位**必须**是 `zh-Hans`。220dpi 够用。
2. Vision 会**静默丢整行**（丢的多半正是加粗的条目行），要靠行距异常检测补回。
3. Vision 会把一行**切成几块**，必须按行合并，且要防着把词头行并进上一行。
4. 判据宁窄勿宽：每加一条过滤都先量误伤，宽判据清得多但会误删正经条目。
5. 子 agent 遇到残片会自己**猜**一条填上，必须在渲染层用「与原始行有无实质公共内容」剔除。
6. 缓存按上游序号存，**清洗一律做在渲染层**。
7. 例句**优先用原书的**，只有原书那句被 OCR 毁了才退回自拟，并标「（自拟）」。
8. 排 PDF：playwright 自带 Chromium；量行数要 `viewport` 等于版心宽 + `emulate_media("print")`；
   行数用 Range 行盒实测；缩完字号要回弹，别缩过头浪费宽度；边框宽度 Chrome 改不动，
   要粗线得用背景渐变画。

## 这本书自己的四条判据（细节在 data/progress.md）

1. **词头只能靠音标认，字号判据不可用**：`muss /mʌs/` 的行高跟正文一样。
   但**音标里绝不能有汉字**，否则续行 `sb /sth or to do sth 渴望…for/`
   会冒充词头 `sb`，把整段释义领走（假词头 1020 个）。
2. **排不进字母序的词头就是假的**（`call` 词条里的 `brigade /…`）。
   取最长不下降子序列，被挤掉的条目还给前一个活着的词头。
3. **合并碎行要先按 y 聚条带、带内再按 x 排**，还要认「顶格的碎片一定是新行开头」。
   少了这条，`brighten sth ˈup` 会把下一条 `brighten ˈup` 的首行顶到自己头上。
4. **gapfill 补出来的行会把几个不相邻的物理行拼成一条**（一条顶三条）。
   判据是「带 fill 标记 + 重音符号 ≥ 2 个 + 长度 > 40」整条丢。
   **重音符号一定要在 normalize 之后数**——原文里它还是 ASCII 单引号，
   直接数 `[ˈˌ]` 一个都数不到，判据等于没写。

## 排版：例句列是「地板列」

`SHRINK_JS` 只把一列当地板列的话，这本书的例句列（一条常给两三句例句、
每句带中译）会被硬压成两行、缩到 5pt，旁边几列还是 7pt，用户一眼就看出来。
**短语动词列和例句列都要当地板列**：各自有行数上限（6 行 / 8 行），
压完取较大值当这一行的地板，其余列上限取 `max(2, 地板)`。
另外**「中英连排」只能在例句列做**——释义列的 `<br>` 隔的是中文释义和英文释义，
拆掉两段会糊成一坨。改完 6pt 以上从 75.9% 升到 96.2%。

## 自查：判据住在 09_clean，08_audit 只负责调用

925 → 532 → 147 → 50 → 19 → 0 处。两条最贵的教训：
- **语域标签摘不干净是最大一类（804 处）**。右括号被扫描件吃掉时不能写成
  「懒惰匹配到第一个空格」——`(AmE, informal to defeat sb…` 只吃掉 `AmE,`。
  要**逐个词往下吃，吃到第一个不是标签词为止**；义项号切开后每段开头还要再摘一遍。
- **收尾 strip 不能带上左括号**：`(of sth) (AmE) to become older…` 的第一个括号
  是主语限制，剥了它整句括号就不配对（377 处）。
- **一个字都标不粗的例句多半不是这条的例句**，拿加粗当最后一道对账。
  为此 `bold_ex` 要放在 `09_clean` 里——清洗要用它，而 09 不能反过来 import 07。
- **`•` 夹在汉字中间是外国人名的间隔号**（`斯嘉丽•约翰逊`），
  清例句引导符 ◇ 的残渣时不能一刀切地删。

## 一致性第一判据：短语动词的第一个词就是它的动词

拿它跟词头对账，全书 426 条（8.7%）对不上，分三种（`fix_pv_word`）：
词头行被 OCR 吞掉（十几条挂到上一个词头名下 → 拿条目里的动词认回来）、
拼写变体（`bail` 下写 `bale ˈout` → 改成词头，别另开词条）、
动词整个没了（`ˈout of sth`、以小品词打头的 → 整条不印）。

三个连带的坑：
- **替换时不能用 `\b`**：重音符号 ˈ ˌ 是 Unicode「修饰字母」、算 `\w`，
  `ˌbale` 里的 bale 前面没有词边界，`re.sub(r"\bbale\b", …)` 根本不触发。
- **认回来的词头要两边都卡字母序**（不小于上一个、不大于后面第一个原书词头）。
  只卡左边的话 `curtain`、`self`、`themselves` 插在中间照样过得去。
- `close()` 卡不住 `bale`/`bail`（差两处又不是相邻换位），要另写
  「等长 + 首字母相同 + 最多差两个字母」的英美变体判据。

## 短语动词列：分号处折行

一条词条常写好几个变体，原书用分号隔开（`ˌwrite sb/sth ˈin; ˌwrite sb/sth ˈinto sth`）。
挤在一行既读不清、又把格子撑宽、右边留一大片白。**分号处折行、分号删掉**，
一行一个变体。**只在括号外面切**——`(BrE also ˌswing ˈround, ˌswing sb/sth ˈround)`
括号里的分隔是同一个变体的说明。

## 两条最容易再犯的

**一、义项号一个都不要印。** 清洗会丢掉同一条短语动词的部分义项，
剩下一个孤零零的「1」而没有「2」（1156 个格子里 644 个只有 1 号），
读者看到它没有任何参照。渲染层不印，`clean_gloss` 里也要把中文开头的
`1`/`①`/`Ⅰ` 剥掉。顺带：英文释义里出现任何数字都是 OCR 把字母认成了数字
（`to not 80 near`=go），短语动词里的数字要卡「任何数字」而不是「孤立数字」
（`give sb ˈup1` 卡不住）。

**二、从搭配词典拷 `clean_cn` 过来时，`[0-9A-Za-z|｜]+ → ；` 这条只能用在释义列。**
那本书用它清「竖线被认成 1」的碎渣，用到例句译文上就是灾难：
`占所有举报罪案的28%` 印成 `占所有举报罪案的。`、`超过了500英镑` 印成
`超过了英镑`。`%$£€` 也不能进「怪符号」名单。
